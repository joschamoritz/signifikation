## 3. Technologie-Entscheidungen

### UI-Framework: **Shadcn/ui + Tailwind CSS**

**Begründung:**
- ✅ Kein Framework-Overhead (Copy-Paste-Components)
- ✅ Einfach an Corporate Design anpassbar (Gentium Plus, DM Sans, Rot `#9b1c1c`, Gold `#c9a84c`)
- ✅ Filament-ähnliche UX (moderne Admin-Ästhetik)
- ✅ Radix UI Primitives (Accessibility out-of-the-box)
- ✅ TypeScript-ready, aber auch mit JS nutzbar
- ✅ Keine Runtime-Dependencies

**Alternative (abgelehnt):**
- Ant Design: Zu "corporate", schwer anzupassen, große Bundle-Size
- Mantine: Mehr Overhead, CSS-in-JS

### Stack (unverändert)
- **Frontend:** React 18 + Vite 6
- **Backend:** Express 5 (ESM), Node.js
- **Datenbank:** SQLite (WAL-Mode)
- **Deployment:** Hetzner VPS (Nürnberg), PM2, nginx

### Design-Anforderungen
- **Responsive:** Desktop-First, aber auch mobil nutzbar
- **Corporate Design beibehalten:**
  - Schrift: Gentium Plus (Headwords), DM Sans (UI)
  - Farben: Rot `#9b1c1c`, Gold `#c9a84c`, Hintergrund `#faf9f7`
  - Wörterbuch-Ästhetik (Duden-Stil)
- **Max-Width:** 1200px (Dashboard), 680px (Formulare)

### Caching-Strategie

**In-Memory-Cache für Kalender (ändert sich selten):**
```js
// server/store.js
let kalenderCache = null;
let kalenderCacheTime = 0;
const CACHE_TTL = 60000; // 1 Minute

export function getKalender() {
  const now = Date.now();
  if (kalenderCache && now - kalenderCacheTime < CACHE_TTL) {
    return kalenderCache;
  }
  kalenderCache = db.prepare('SELECT * FROM kalender ORDER BY datum').all();
  kalenderCacheTime = now;
  return kalenderCache;
}

// Cache invalidieren bei Änderungen
export function updateKalender(datum, ids) {
  // ... DB-Update
  kalenderCache = null; // Cache invalidieren
}
```

### Zod-Validierung

**Alle neuen Endpoints mit Zod validieren:**
```js
import { z } from 'zod';
import { validate } from '../middleware/validate.js';

// Schema
const updateUserRoleSchema = z.object({
  body: z.object({
    role: z.enum(['user', 'admin'])
  }),
  params: z.object({
    id: z.string().regex(/^\d+$/).transform(Number)
  })
});

// Route
router.patch(
  '/users/:id/role',
  validate(updateUserRoleSchema),
  async (req, res) => {
    // req.body.role und req.params.id sind validiert
  }
);
```

**Wichtig (Express 5):** `req.query` ist read-only → `Object.assign` verwenden:
```js
// middleware/validate.js
if (source === 'query') {
  Object.assign(req.query, result.data); // ✅ Korrekt
  // req.query = result.data; // ❌ Fehler in Express 5
}
```
